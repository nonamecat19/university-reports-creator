# 08 — AI Assistance (service-ai)

## Purpose

A separate Python service exposing AI features through a provider-abstraction layer. **Local-first: Ollama is the default provider**; cloud providers (OpenAI, Anthropic, OpenRouter) are pluggable via configuration. Features: text generation/assist, whole-document analysis surfaced as review comments, Ukrainian grammar/style checking, and source assistance.

## Provider abstraction

- **FR-AI-01** `service-ai` (Python, gRPC via `pkg/shared-py` — FR-ARC-16, `:50055`) defines an internal `LLMProvider` interface: `complete(messages, options) -> stream`, `capabilities()` (max context, JSON-mode support). Implementations: `ollama` (default; via Ollama HTTP API), `openai`, `anthropic`, `openrouter`. Selection + model names via env (`AI_PROVIDER=ollama`, `AI_MODEL=...`, `AI_FALLBACK_PROVIDER=` optional), never hardcoded.
- **FR-AI-02** Model guidance for the default local setup: a multilingual instruct model with solid Ukrainian (e.g. gemma3 / qwen3 class, ≥ 8B recommended) — the concrete default lives in `.env.example` + docs, not code. Context budget management: requests larger than the provider's context are chunked or scoped (per-section) automatically; structured tasks require JSON output with schema validation and one retry-on-invalid.
- **FR-AI-03** All AI calls stream (server-streaming RPC) so the editor renders tokens progressively; cancellable from the client.
- **FR-AI-04** Privacy stance documented in-product: with `ollama`, document text never leaves the machine/cluster; selecting a cloud provider shows a one-time consent notice. No document content is logged (only sizes/latency/model ids).
- **FR-AI-05** Limits: per-user concurrent AI request cap (default 2) and per-minute request cap; long analysis runs as a cancellable job. Applies at the gateway ([12-non-functional.md](12-non-functional.md)).

## Features

### A. Text generation / writing assist (in-editor)

- **FR-AI-06** Editor integration points:
  - **Draft section**: generate a first draft for a section from document topic + section title + user-supplied bullet points; inserted as clearly AI-marked pending content the user confirms into the document;
  - **Continue writing** from cursor (uses preceding section text as context);
  - **Selection transforms**: rephrase, expand, condense, translate uk↔en, convert to academic style (removes colloquialisms, first person → impersonal constructions per Ukrainian academic convention);
  - results appear in a diff-style preview (original vs proposed) → apply/regenerate/discard; applying in suggest mode creates suggestions instead of direct edits.
- **FR-AI-07** Context assembly: system prompt (academic-Ukrainian writing rules, report type) + document metadata (topic, type) + section outline + local text window. Prompt templates versioned in the service repo (`service-ai/prompts/`), not inlined in code.

### B. Document analysis → review comments

- **FR-AI-08** "Analyze document" action runs a structured whole-document review producing findings: `{section_id, anchor_text, severity, category, message}` with categories: structure (missing/empty required parts, intro lacks об'єкт/предмет/мета/завдання), topic relevance (section content vs declared topic), conclusions consistency (висновки cover stated tasks), coherence (logical gaps, repetition), formatting-semantics (tables/figures never referenced in text, uncited sources).
- **FR-AI-09** Findings are inserted as **comments with the `ai` author badge** into the standard review system ([07-review-mode.md](07-review-mode.md) FR-REV-08), anchored by fuzzy-matching `anchor_text`; unanchorable findings attach at section level. Re-running analysis resolves obsolete AI comments (whose anchors/issues disappeared) rather than duplicating.
- **FR-AI-10** Analysis is JSON-mode with schema validation; oversized documents are analyzed per-section with a final cross-section pass (structure/conclusions checks need the outline + intro + conclusions together).

### C. Grammar & style (Ukrainian academic)

- **FR-AI-11** Two-tier checking:
  - tier 1 (deterministic, fast): **LanguageTool** (self-hosted, uk) integrated by service-ai for spelling/grammar/punctuation — reliable inline squiggles without LLM latency;
  - tier 2 (LLM): style pass per section on demand — канцеляризми, tautology, anglicisms, non-academic tone, overlong sentences; output as ranges + replacement proposals.
- **FR-AI-12** Results render as inline highlights with hover-cards (message + one-click fix). Applying a fix is a normal edit (or suggestion in suggest mode). Dismissals persist per range+rule so re-checks don't resurrect them.

### D. Source assistance

- **FR-AI-13** Parse freeform pasted reference strings into CSL-JSON (backing [06-bibliography.md](06-bibliography.md) FR-BIB-04), fill_status `needs_review`.
- **FR-AI-14** **Citation-source consistency**: for a selected claim with a citation, or for all citations in a section (given source abstracts/metadata are available), flag citations where the source plausibly doesn't support the claim — advisory only, rendered as AI comments.
- **FR-AI-15** **Source suggestions**: from topic + section text, propose search queries and candidate source types; when a web-search capability is configured (optional, provider-dependent), return candidate sources as unconfirmed `needs_review` entries. Never fabricates: sources without a resolvable identifier/URL are presented as "search suggestions", not as sources.

## UX notes

- Right-panel **AI tab**: action list (analyze, grammar pass, draft…), streaming output area, history of runs for the session.
- Every AI insertion into content is visually attributed until confirmed; an "AI usage" note is available (academic-integrity transparency; universities differ in policy — the tool assists, the student is responsible).
- Global kill-switch: `AI_ENABLED=false` hides the tab and disables RPCs (deploys without a GPU box).

## Acceptance criteria

- With only Ollama running locally, all four feature groups work end-to-end; switching `AI_PROVIDER=openrouter` via env requires no code change.
- Draft/transform flows stream, are cancellable, and never modify the document without explicit apply.
- Analyze on a fixture document with known defects (missing conclusions coverage, unreferenced table, empty section) yields AI comments anchored at the right places; re-run does not duplicate them.
- LanguageTool flags seeded uk spelling/grammar errors inline in < 2 s per section.
- Freeform reference string parses into a CSL-JSON draft requiring confirmation.

## Open questions

- Whether tier-2 style checks run automatically on save (cost/noise) or on demand only (MVP: on demand).
- GPU expectations for local Ollama in docs (minimum model that is acceptably good for Ukrainian).
